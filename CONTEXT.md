# Development workflow skills

Skills for configuring and using a bounded, evidence-driven development workflow.

## Language

**Skill catalogue**:
The selected skill sources, versions, dependencies, purposes, and installation groups. It is not a list of every available third-party skill.

**Environment setup**:
Preparing skill availability and an agent application's configuration for a selected workflow. Installing skill files and configuring the application are separate steps.

**Workflow owner**:
The procedure responsible for a phase such as discovery, execution, or review. Selecting an owner avoids stacking overlapping procedures for the same phase.

**Verification contract**:
The agreed observable behavior, testing boundary, required cases/checks, non-goals, scope-reopening conditions, and completion criteria for a change.

**Intent anchor**:
The authoritative explanation of a feature or architecture change's purpose, desired outcome, direction, and boundaries. It can be an existing approved brief or part of a specification, not necessarily a separate document.

**Change explanation**:
The reason and chosen approach communicated with a concrete change, grounded in its actual scope and approved intent rather than a file-by-file restatement of the diff.

**Execution record**:
Local recovery state for an initiative: authoritative work references, task ownership, partial changes, applicable verification/review evidence, unresolved questions, and the next action. It is separate from durable project intent and from a conversation transcript.

**Acceptance**:
The coordinator's conclusion that approved behavior, required verification, and blocking review findings have been satisfied or explicitly waived by an authorized decision. A worker's completion report alone is not acceptance.

**Learning checkpoint**:
A nonblocking opportunity to propose reusable guidance or automation from observed evidence and expected repetition. It does not authorize changing or deploying skills.

**Execution adapter**:
A procedure that turns approved requirements into bounded worker assignments and reviewed results using the capabilities supplied by the agent application.

**Application integration**:
Configuration that maps portable workflow roles to an application's models, worker tools, and permissions.
_Avoid_: Host, when it could be confused with operating system.
